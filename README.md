## 使い方

1. PX-100 MIDI OUT → CME U2MIDI Pro → Chromebook の接続を使い、Chromeで公開URLを開きます。
2. 「MIDI接続」を押し、Chromeで許可します。`U2MIDI Pro MIDI 1 / CME Pro` を確認します。
3. 「曲ライブラリ」の「練習する曲」で内蔵曲を選びます。初期選択は「きらきら星」。「練習の開始位置」で最初から／指定小節を選び、「練習開始」を押します。指定小節の最初の新規打鍵から始まり、タイ継続や休符は再打鍵対象にしません。
4. 「できるまで」では正しい音で次へ、間違った音では「もう一度♪」と表示して待ちます。「通し練習」では正誤を記録し、間違いでも次へ進みます。練習方法の変更は現在指定している開始位置の待機状態へ戻ります。
5. 同じ音が続くところは、鍵盤を離してからもう一度押してください。
6. 選択曲の最後まで弾くと終了します。通し練習では正しく弾けたステップ数と確認したい小節を表示します。「もう一度」で結果を初期化し、その練習セッションの開始位置から再開できます。音数はきらきら星14音、ドレミの練習7音、短いメロディ5音です。

内蔵曲の「マイム・マイム連弾（once版／original版）」を選ぶと、一人連弾の設定が表示されます。「練習対象パート」でPRIMOまたはSECONDOを選び、「相手パート自動再生」を「あり」にすると、反対側のパートをMIDI出力で鳴らします。**U2MIDI Pro MIDI OUT → PX-100 MIDI IN**の接続も必要です。「手本を聴く」は自分の選択パートを再生します。

相手ありの「できるまで」は曲の区切りまで相手が鳴り、正解していれば次へ、まだなら発音を止めて待ちます。遅れて正解したら相手も続けます。連弾の「通し練習」は相手なしでも曲の速さで最後まで進み、無入力を不足として記録します。開始位置は最初／現在位置（反復回数を保持）／指定小節を選べます。「もう一度」はそのセッションの開始位置から。「連弾練習を停止」で時計と発音を停止します。パート・相手・手・練習方式・開始位置の変更時も停止し、待機状態に戻ります。

PRIMOは主旋律の右手単旋律で118音（original反復込み218音）、SECONDO両手は109ステップ（original反復込み204）。冒頭4小節は終盤のフレーズによる前奏、5〜30小節が主旋律です。既存の自分の曲や原譜PDFは保存したまま利用できます。PRIMO MusicXML/MXL/PDFと2パート確認用MusicXML/MXLは連弾の設定内から取得できます。2パート確認用データは楽譜ソフト用です。

練習中・手本再生中にも曲を変更できます。変更時は発音と予約を停止し、進捗をリセットして新しい曲の待機状態になります。MIDI接続と機器選択は維持します。読み込み中・失敗時は練習と手本を開始できません。失敗したら別の曲を選んでください。

「＋ 曲を追加」から `.musicxml` / `.xml` / `.mxl` を選び、曲名・作曲者・対応状況を確認して「追加する」を押すと「自分の曲」に保存されます。追加曲はこのブラウザのIndexedDBに保存し、GitHubやサーバーへ送信しません。ページ再読み込み・ブラウザ再起動後も保存領域が残っていれば復元します。サイトデータの削除やプライベート閲覧の終了では失われるため、元のファイルは保管してください。

登録確認の「楽譜解析結果を確認」で小節範囲・Staff・Voice・和音・休符・タイ・手本テンポ・対応状況を確認できます。選択後は「開発者用」でも確認できます。通常画面の現在小節は、PracticeTargetのXML小節番号に従い、練習・手本のカーソルと一緒に進みます。範囲は固定4小節にせず、読み込んだXMLを使用します。検証レポートは構造検査であり、印刷譜との音符の一致を保証するものではありません。

単旋律曲は「選択」で既存の練習・手本演奏を使えます。対応範囲の和音・2Staff・複数Voice・休符・通常のタイを含む曲は「音程練習対応」と表示します。2Staff曲では「練習するパート」の右手・左手・両手を選びます。初期選択は両手です。開発者用の「Score解析」でStaff・Voice・練習Step・期待音などを確認できます。複数Partなど解析範囲外の曲も原文を保存でき、未対応理由を表示します。「削除」→画面内の「削除する」で追加曲と紐付く元の楽譜を削除できます。選択中の曲を削除すると発音・予約を停止してきらきら星へ戻ります。

「自分の曲」の「元の楽譜を登録」でPDFまたは画像を選び、ファイル名・形式・サイズを確認して登録します（1曲1ファイル、30 MiB以下）。元の解像度とファイル内容を保ったBlobを同じブラウザのIndexedDBへ保存し、外部へ送信しません。「元の楽譜を変更」「元の楽譜を削除」も画面内の確認後に実行します。元の楽譜だけを削除してもMusicXMLは残ります。

登録した曲の楽譜上部で「練習用楽譜／元の楽譜」を切り替えられます。元の楽譜は参照表示です。正解・音価・演奏順は引き続きMusicXMLに従います。元の楽譜を見ながら弾いても練習は進み、手本も継続します。戻ると現在位置・不足音を表示します。進行していない間の各ビューのスクロール位置は別々に保持します。PDF上の位置同期・赤表示・変換機能はありません。パスワード付きPDFは非対応です。

「できるまで」の和音は最初の必要音から300ms以内に必要な音がすべてそろうと、入力順に関係なく1ステップ進みます。途中は「音をそろえてみよう」、不足・余分な音は「もう一度♪」。楽譜上部に結果と「足りない音」「ちがう音」を表示し、不足した正解の符頭だけを赤くします。余分な音符は描きません。鍵盤を離して弾き直すと赤表示を解除します。単音は待たずに判定します。休符・選択パートに音がない位置・タイ継続音は再打鍵を要求しません。曲やパートを変更すると練習・手本・発音を停止します。パート変更は同じ指定小節で開始位置を再解決し、曲変更は先頭の待機状態へ戻ります。

「通し練習」の和音は最後の新しい音から100ms、最初の音から最大300msでまとめ、正誤にかかわらず1ステップ進みます。結果はセッション中に保持し、終了後も小節単位で確認できます。再読み込み後の履歴保存は行いません。無音で飛ばした音やリズム・テンポは評価しません。原譜表示中の「原譜で全画面練習」では、練習・手本を継続したままPDF／画像を大きく表示し、50〜200%のズームと内部スクロールが使えます。「× 全画面終了」またはEscで戻ります。

練習開始前のMIDI入力はデバッグ表示のみ更新します。開発確認用の「前の音／次の音」は「開発者用」を開くと使えます。誤操作を避けるため、練習中・完了後は手動移動を無効にします。

「楽譜全体」の青い枠は大きな楽譜の表示範囲、緑線は実際の現在位置です。手動で別の場所を見ても緑線は現在位置に残ります。見出しで折りたためます。ミニマップをタップして移動する機能はありません。

長い楽譜は楽譜パネル内で縦・横にスクロールできます。小節・進捗・フィードバック・「現在位置へ戻る」はパネル上部に残ります。練習では現在の段の最後の打鍵対象小節に入ると、現在の音符を残しながら次段を先に見せます。手本では次段の最初の発音より原則750ms前に先読みします。緑帯は実際の現在位置を示し、先へ動かしません。手動スクロールを常時上書きせず、「現在位置へ戻る」では先読みを外して現在の緑帯へ戻ります。

反復の戻り先は、練習では最後の正解入力直後、手本では最後の音が鳴り始めてから戻り先の発音より前に、即時表示します。手本の遠距離反復を先読みしている間、緑帯はまだ元の小節にあるため画面外になります。画面の広さに応じて楽譜の倍率を100%以上の範囲で調整します。極端に狭い画面や段間が広い楽譜で2段が収まらない場合は、現在の音符を優先します。

指定小節からの手本開始、手本終了・停止、もう一度、パート変更、曲変更では、対応するカーソル位置と表示範囲を即時に合わせます。通常の進行は滑らかに移動し、OSでアニメーションを減らす設定の場合は即時移動します。楽譜を見られる状態にするため、必要な場合だけページ自体も楽譜パネルまで戻します。

特定の曲に合わせた小節数制限はありません。従来の取込保護上限（note/rest合計1000要素・500小節、XML/MXLのサイズ等）は維持します。長さ以外の記譜対応範囲も変えていません。

300msは和音をまとめる許容幅です。練習時のリズム・テンポ・音の長さ・強弱・ペダルの評価、AI・点数・履歴保存は今回の対象外です。アルペジオ・特殊な装飾・連符などは安全に評価できる範囲へ単純化せず、練習・手本を無効にします。

## 手本を聴く

1. MIDI出力の接続済み表示を確認し、「手本の開始位置」で「最初から」「現在位置から」「指定小節」を選んで「手本を聴く」を押します。選択曲・選択パートの指定位置へカーソルを移してからPX-100本体へ送信します。同じ和音は同じtimestampで発音し、各音価に応じて停止します。
2. MusicXMLの数値テンポを優先し、指定がなければSongのtempoBpm、それもなければ100 BPMです。1拍は `60000 / BPM` ms。116 BPMでは約517.24msです。従来どおり音価の90%の位置にNote Offを入れます。
3. 「停止」で途中停止します。再度「手本を聴く」を押すと選択した開始位置から再生します。指定小節に対象音がなければ次の対象音から始め、以降にもなければメッセージを表示します。
4. 最後のNote Offで「手本の再生が終わりました」と表示します。終了・停止後は元の練習位置と進捗へ戻り、練習中なら続きから弾けます。「もう一度」で練習の先頭へ戻せます。

D3.3.2では再生中の同時刻の全MIDI音を先に送信し、その直後にカーソル表示を更新します。長い反復の戻りでは、途中の全位置を描画せず移動先だけを描画します。先読みは従来どおり別の表示通知で行い、音楽の時間軸や停止処理へ触れません。「開発者用」→「Demo MIDI Trace」→「ログを更新」で指定timestampと送信順を確認できます。ログは直近2048件をメモリにだけ保持し、自動更新・外部送信・永続保存をしません。

通常のタイはつながる音価をまとめ、中間の再発音をしません。休符はonsetの間隔で無音になります。同時刻の同じpitchは1回にまとめ、長い方の音価を使用します。XMLの途中の数値テンポ指定も、その位置以降に適用します。タイや長い音がテンポ変更をまたぐ場合も区間ごとの時間を合計します。再生速度の選択もこのテンポ計算を使用します。演奏テンポの評価は追加していません。

手本を押すと、練習位置・正解数を保持して `demoPlaying` に切り替え、途中の和音判定と赤表示を解除します。手本中の鍵盤入力・MIDIループバックはデバッグ表示だけに反映し、正誤判定を行いません。途中再生の開始点でまだ持続している音・タイは、その残りの長さを新しく発音して再現します。MusicXMLを唯一の原本として、同じXMLからOSMDの楽譜と `ScoreModel` の音高・音価を生成します。曲の音列を別途ハードコードしていません。

予約を消せない環境での確実な停止を優先し、未来のNote Onをまとめてキューへ送りません。開始時刻から計算した絶対時刻で1音ずつNote Onを送り、Note OffはMIDIのtimestampで予約します。D3.3.1では表示更新の失敗や大きな遅延だけで手本全体を停止しません。発音期限を過ぎた音はまとめて鳴らさず、元の時間軸で次の音へ進みます。別タブへ移った場合は従来どおり停止します。停止直後、残ったNote Offが過ぎるまで操作が一時的に無効になる場合があります。[今回の再生・停止設計](docs/PHASE2ED331.md)

練習の途中・完了後も、手本の「最初から」は常に演奏順の先頭から始めます。完了後の「現在位置から」は「練習が最後まで終わっているため、最初から手本を再生します」と表示して先頭から再生します。練習中の「現在位置から」は反復回数も保ちます。再生状態・タイマー数・出力中の音の送信記録は「開発者用」の「手本再生の診断」で確認できます。

指定位置から曲末までの再生に対応します。MusicXMLの単純forward/backward反復は練習・手本とも演奏順へ展開します。小節指定は最初の出現位置、「現在位置から」は現在の反復回数を保ちます。「マイム・マイム」original版は1〜30→5〜30、右88／左144／両手204Stepです。反復情報のないonce版は従来どおりです。終了位置を選ぶ部分練習、楽譜タップによる開始、複雑な演奏順（ending・D.C.等）は追加していません。メトロノームの対応範囲は後述します。

## 再生速度（Phase 2の拡張）

楽譜の上にある「再生速度」で50％・75％・100％（通常）を選びます。手本と相手パートで共通の設定です。50％は通常の2倍の時間、75％は約1.33倍の時間で再生します。音高・音列・楽譜のテンポ表記は変更しません。

MusicXML→曲メタデータ→100 BPMという既存のテンポ優先順位を維持し、確定した各テンポへ倍率を掛けます。途中のテンポ変更、休符、和音、タイの持続、90％ゲートのNote Off、指定小節／現在位置／反復2回目からの開始も同じ時間軸を使います。先読み表示は選択速度の発音時刻を基準とし、既存の原則750ms前という余裕を維持します。両方のパートの小節や音列を書き換えません。

相手ありの「できるまで」は選択した速さの区切りで正解を待ち、誤りでは従来どおり停止・消音します。連弾の「通し練習」は相手あり／なしのどちらも選択速度で進みます。単独曲と相手なしの「できるまで」は入力で進む従来方式です。和音をまとめる300ms、通常の通し練習の100ms／300ms、正解の音、打鍵対象、正解数、終了条件には速度を適用しません。練習中に手本を聴くときの進捗保持とMIDI入力除外も維持します。

再生・連弾練習中（正解待ちを含む）は速度欄を無効にします。「停止」または「連弾練習を停止」で止めてから速度を変更し、再び開始してください。通常の入力式練習中に速度を変えても進捗や判定をリセットしません。曲・パートの変更でも速度の選択は保持し、再読み込み／アプリの再起動で100％へ戻ります。元PDFの全画面では「練習・手本の操作」を開くと速度を選べます。MIDIの許可や機器選択は保持します。MIDIOutput.clearのない環境では、停止後に古いNote Offが過ぎるまで操作を待つ既存処理も維持します。

## メトロノーム（Phase 2の拡張）

楽譜上部の「メトロノーム OFF」をタップしてONにし、手本または連弾練習を開始します。初期値はOFF。クリックはWeb Audioで合成して**Chromebookのスピーカー／選択中の音声出力**から鳴ります。PX-100へ送るMIDI音とは別です。再生中もON/OFFでき、ONは次の拍から加わり、OFFは発音中のクリックも止めます。曲・パート・表示切り替えでもON/OFFの選択を保持し、再読み込みでOFFに戻ります。原譜の全画面では「練習・手本の操作」を開くと同じ設定を操作できます。音声の起動に失敗した場合はクリック側にエラーを表示し、MIDI演奏を継続します。OFF→ONで音声を再準備できます。

MusicXMLの拍子を小節ごとに継承してScoreModelへ保持し、既存のテンポ解決・時間積分・演奏順を使用してクリックを作ります。4/4は4分音符、2/2（マイム・マイム）は2分音符、6/8（刈り入れ時）は付点4分音符のクリックです。6/8・9/8・12/8等は3つの8分音符を1拍としてまとめ、3/8は8分音符を使います。小節頭は高く強い音、他の拍は低く弱い音にします。弱起を小節頭として強調せず、拍子のない楽譜・3+2等の加算拍子・無拍子・Staff間で異なる拍子・小節途中の拍子変更は、4分音符の等しいクリックへフォールバックします。新しい拍子解釈で練習対応可否や判定を変更しません。100,000拍を超えるクリック列は生成を中止し、手本・連弾の演奏をクリックなしで継続します。

## npmパッケージ

Phase 2E-BではMXL展開にJSZip 3.10.1を直接依存として追加しました（以前はOSMDの間接依存）。IndexedDBはブラウザ標準APIを使用し、追加ラッパーはありません。

Phase 2E-C1ではNode単体テスト用に `@xmldom/xmldom 0.9.12` を開発依存へ追加しました。公開アプリのParserはブラウザ標準のDOMParserを使用します。DBは引き続きversion 1で、既存曲のXML・メタデータを書き換えません。
