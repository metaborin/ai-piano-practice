# Phase 2拡張：マイム・マイムの一人連弾

2026-10-12。Phase 3には進みません。PRIMO作成と単独取り込みの確認を終えてから、連弾の実装を行いました。楽譜の詳細は [第1段階の検証レポート](PHASE2-DUET-SCORES.md) を参照してください。

## 1. 実装した動作

内蔵曲に「マイム・マイム連弾（once版）」と「マイム・マイム連弾（original版）」を追加。最初は従来のきらきら星を選択します。連弾曲の初期パートは既存SECONDO、相手再生はなし。曲を取り込み直す操作は不要です。既存の自分の曲・原譜を消したり移行したりしません。

- PRIMO/SECONDOを選び、その単体MusicXMLを表示・解析・判定・手本に使用。
- 相手ありは反対側のMusicXML全体をMIDI出力。自分の右手/左手/両手の選択は相手の再生範囲を変更しません。
- 手本ボタンは選択した自分のパート（選択した手）を再生し、練習判定を停止。
- 相手なしの「できるまで」は従来の入力で次へ進む処理を利用。
- 相手ありの「できるまで」は現在の対象から次の対象まで相手を鳴らし、正解なら音楽時間の区切りで進む。未正解なら区切りで相手の音を停止して待機。正解したら続きから再開。正解入力で曲の時計より先へ飛ばしません。
- 連弾の「通し練習」は相手なしでも時計に従って最後まで進む。入力された音を各対象の区間で集め、正解・不足・余分を記録。無入力は不足。従来の一般曲の通し練習は入力ごとの記録を維持。
- 終了後のステップ別結果と確認したい小節を表示。履歴の永続保存・精密リズム採点は追加しません。
- 最初／現在位置／指定小節から開始。現在位置は反復回数を保持し、開始ボタンを押す時点の最新位置を使用。「もう一度」はそのセッションの指定開始位置へ戻る。
- 曲・パート・手・相手・方式・開始位置の変更、連弾停止、全音停止、出力切断、非表示・ページ離脱・PWA更新で時計と発音を停止。MIDI許可や入力ハンドラーの作り直しはなし。

## 2. データと読み込み

`Song.duet`に安定した曲ID、既定パート、2パートの名前・MusicXML参照を持たせます。一般曲は従来どおり。`duetSongs.ts`はMusicXMLのURLと説明だけを登録し、正解や手本用の音列は持ちません。

`SongSelection`は選択したXMLと相手XMLを同時取得。相手を既存パーサーで解析し、表示側は従来どおりScoreViewで同じXMLをOSMDとパーサーに渡します。OSMDの初期表示とカーソル対応の準備完了後に、小節の番号・開始拍・長さ、テンポ、反復の一致を検証し、両Planを操作可能にします。片側の取得/解析/整合検証や表示が失敗すれば両側を無効にし、前の楽譜・判定を残しません。別の曲/パートで復帰できます。

要求IDで古い取得結果、解析、OSMD完了/失敗を無効化。ScoreViewの要求ごとに分離したOSMDホストと後始末を維持。取得後のXML反映を読み込みから分けた設計を利用します。

## 3. 再生と判定の分離

`DuetPlan`は両ScoreModelを検証し、既存の反復展開とテンポ積分から共通の小節時刻・自分の対象時刻を生成。相手の音は既存 `buildDemoPlan` の音価・タイ・90%ゲート・テンポ処理から作ります。両パートの対象数は異なっても、小節の演奏順が一致するので同期できます。

`DuetController`はDOM/React/OSMDから独立した時計。自分のPracticeSessionだけへ対象の区切りを通知し、相手の音だけをMidiOutputManagerへ送ります。正解している連続区間では長音のNote Offを区切りで切り直さず、反復も同じ展開タイムラインで送信します。待機に入ったときは残音を止め、再開時にはその位置で必要な相手の長音を復元して再発音します。

PracticeSessionには時計付きの2方式を追加。`paced`は既存MomentMatcherの正解を保持して区切りで進行。`timed`は区間の入力を集め、既存PracticeAttemptResultに変換して進行。一般曲は`input`の既存動作を使用します。全方式とも同じ1つのMIDI入力購読で処理し、鍵盤の離鍵を必要とする連続打鍵を維持します。出力送信中の同期ループバックは判定から除外します。

音の停止・予約の扱いは既存MidiOutputManagerを再利用。未来のNote Onはキャンセル可能なJSタイマーだけで予約し、Note OffはMIDIポートへ時刻指定。停止は世代番号を更新して全タイマー/購読を解除し、個別Note OffとCC123を送信。`clear()`がない環境では古いOffの期限まで再開を待ちます。遅延した古いタイマーを強制実行しても新しい練習/再生を変更しないことを検査しています。

期限から150ms以上遅れた相手の発音は、既存Demoと同じ方針でスキップし、過去の発音をまとめて鳴らしません。非表示にした場合は停止するため、タブを切り替えたままの連続演奏はしません。

## 5. 他の連弾曲を追加する手順

1. 各パートを単一PartのMusicXMLとして `src/scores/duet/`へ配置。小節番号・長さ・拍子・テンポ・単純反復を一致させる。
2. `duetSongs.ts`で `?url&no-inline` で両XMLを読み込み、安定IDと `Song.duet.parts` に登録。曲名・説明・既定パートを設定。
3. 両モデル/Planの整合検証と全体再生、片手選択、休符/タイの途中開始、反復、停止をテスト。
4. 必要なら同じXMLからMXL/PDF確認用データを作り、公開時のbase配下に登録。MusicXML以外の正解音列は作らない。
5. mainへpushし既存Actionsを通す。実発音・相性は実機で確認。

## 7. Chromebook + PX-100 + U2MIDI Pro 実機確認（ユーザー受入待ち）

公開URL <https://metaborin.github.io/ai-piano-practice/> を開きます。PWA旧版ならオンラインで「更新を確認」→新しい版の「更新する」を選びます。演奏中の更新は確認画面が出るので、更新後に開始し直してください。画面上部の「Phase 2 · 一人連弾」と内蔵5曲を確認。

接続はPX-100 MIDI OUT→U2MIDI Pro MIDI IN、U2MIDI Pro MIDI OUT→PX-100 MIDI IN、USB→Chromebook。「MIDI接続」→Chromeの許可、入力/出力のCME機器を選び、「テスト音 C4」と離鍵表示を確認。以前拒否した場合はChromeのサイト情報→サイトの設定→MIDIを許可して再読み込みします。

## 8. 未確認・制約

Chromebook + PX-100 + U2MIDI Proの実発音、音量バランス、合奏の響き、PRIMOの弾きやすさ、実負荷でのカーソル同期は未確認。実機受入まではPhase 2の連弾拡張全体を完了扱いにしません。
