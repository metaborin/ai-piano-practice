## 3. Look-ahead設計

```text
MusicXML → ScoreModel → PracticePlan / 演奏順Occurrence
        └→ OSMD → ScoreMomentごとの段ID・座標

練習の現在Occurrence＋段ID → 次段のLookAheadTarget
手本の既存発音計画＋段ID  → 表示通知時刻
                             ↓
                 ScoreView → viewportだけ先読み
実際の現在Occurrence ───────→ 緑帯・小節・進捗
```

独自音列や曲ごとの小節番号、固定3音先などは使いません。練習対象にならない休符・タイ継続・選択パートに打鍵がない位置は、既存のPracticePlanどおり扱います。

## 4. 段の判定と描画

OSMDの `GraphicSheet.MeasureList` → `ParentMusicSystem` のオブジェクト同一性で段を識別します。MusicXMLの印刷指示だけでなく、画面幅による実際の折返しも反映します。

描画時に既存CursorMapを使い、ScoreMomentとOSMDカーソルの座標を対応付けます。加線の音符が緑帯の範囲を越える場合も、実際のSVG符頭の上下端を含めます。この採寸中だけOSMDカーソルを走査し、元の位置に戻します。演奏中の先読み目的ではカーソルを先に動かしません。

幅・高さ変更で再計算します。隣接2段が収まる倍率を実測し、通常の最大135%（幅600px未満は110%）から、100%を下限に調整します。収まらない場合は現在段を優先し、次段を可能な範囲まで表示します。小節番号・進捗・結果・不足音等のsticky領域は維持します。

## 5. 練習でのタイミング

現在Occurrenceより先を演奏順に調べ、段が変わる直前のOccurrenceが現在と同じ小節なら先読みします。つまり現在段の最後の**打鍵対象がある小節**に入った時点です。タイだけの最後の小節があっても、その前の打鍵対象小節で準備できます。指定小節からその場所へ練習開始した場合も、最初の打鍵前に先読みします。

時間基準を使わず、次段の最初の正解入力を待ちません。反復へ戻る前は現在の最後の対象を隠さず、正解するまでその場で待ちます。

## 6. 手本でのタイミング

`LOOKAHEAD_MS = 750`。通常の段替わりでは、既存発音計画の次段最初のNote On時刻より750ms前に通知します。ただし現在段に入る前まで先行させず、短い段では現在段の最初の発音の1ms後までに制限します。和音は同じ開始時刻の発音を1つの境界として扱います。

表示用タイマーとMIDI用タイマーを分け、表示完了・smooth animationを待ちません。発音・Note Offに渡すtimestampやテンポ処理は変更しません。実際の位置通知もNote On前に同期反映し、先読み後に手動で移動した場合の境界復帰に備えます。

## 7. Navigation jump

Occurrenceの演奏順が前へ進むのに、参照する原譜Target indexが戻る場合を検出します。5や30という値はアプリ処理にありません。

- 練習：最後の正解を受けた同じMIDIイベント処理内で、Reactの表示を確定。緑帯とviewportを次Occurrenceへ即時移動してから次入力を受けます。複数のMIDI通知がまとめて届く場合も検証します。
- 手本：最後のNote Onより後、戻り先Note Onより前にviewportを戻します。通知は `max(最後の発音+1ms, 戻り先の発音−750ms)`。極端に短い音間隔で先読み余裕がなければ、実発音前の同期表示でも補います。

2回目の通常段替わりも同じ段情報とOccurrenceで処理します。途中開始は、その開始位置から作られた既存発音計画を使用します。

## 8. 通常段と遠距離反復の違い

通常は現在段と次段を同時に収め、現在位置を表示領域上部から30〜40%付近へ置ける範囲で調整します。2段を見せるためにさらに上へ寄せる場合もあります。反復は同時表示できない距離なので、戻り先の表示を優先して即時移動します。

## 9. 緑帯とviewportの分離

表示専用の通知は `preview` に格納し、`currentNoteIndex` と `cursorMomentId` を変更しません。緑帯・小節表示・進捗は実際の現在位置です。遠距離反復の手本先読み中だけは、元の緑帯が画面外になり、上部に元の小節番号が残ります。戻り先が発音すると緑帯もそこへ移ります。

DemoPlayerは段IDと時刻のデータだけを受け取り、React・OSMD・DOMを直接操作しません。

## 10. smooth / instant

- 通常の短い段移動：smooth。OSのアニメーション軽減設定時はinstant。
- 反復ジャンプ、開始、停止・終了からの復帰、再開始、明示的な「現在位置へ戻る」：instant。
- instantの前に進行中のsmoothを打ち切り、古い移動が後から画面を戻さないようにします。

## 11. 手動閲覧と古い通知

スクロールイベントの監視や常時ポーリングはしません。Target進行、先読み予定時刻、反復、開始・復帰・戻る、画面寸法変更のイベントで動きます。停止中の手動スクロールを自動で引き戻しません。

「現在位置へ戻る」は先読みなしで緑帯へ戻し、同じ表示通知で直後に先へ戻さないようIDを消費します。次の明確な進行・段移動で追従を再開します。

停止、曲・モード変更、読み込み失敗では既存の停止処理に加えて表示タイマーも破棄します。世代番号で古い通知を無効化し、再描画時は新しい段の対応表から残りの表示予定を作り直します。機器接続・入力ハンドラーは追加しません。
