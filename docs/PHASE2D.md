## MusicXML・ScoreModel・OSMDの対応

1. 曲一覧の取得関数で `?raw` のMusicXML文字列を非同期取得します。
2. 取得済みXMLを `ScoreSource` として渡し、形式と対応範囲を検証します。取得処理は解析・描画から独立しています。
3. `ScoreView` のOSMDに、その文字列をそのまま渡します。
4. 既存の `readScoreModel` がOSMDのカーソルを先頭から走査し、各打鍵対象のMIDI音高・四分音符単位の音価を得ます。
5. 描画・解析が成功し、要求IDとXML・曲IDが選択中のものに一致した場合だけ、同一モデルをPracticeSessionとDemoPlayerに反映して操作可能にします。

総音数・現在位置の分母・終了条件はモデルの `notes` から求めます。正解用／手本用の曲別配列はありません。休符を含むモデルを打鍵数と混同せず、現在の対応範囲では休符自体をエラーとします。

## 切り替え・停止・古い通知

- 選択イベント中、最初にPracticeSessionを空の待機状態にして判定を停止します。その後DemoPlayerを停止し、モデルを空にします。手本以外にC4テストが発音中の場合も停止します。
- 既存のNote Off・CC123 / All Notes Offを使用します。再生タイマーを解除し、世代番号を更新します。旧タイマー、再生完了、旧MIDI出力の中断通知は新しい状態を変更しません。
- 未来のNote OnをまとめてMIDIへ予約しない方式を維持します。MIDIの `clear()` がない場合も新しいNote Onは送られません。残ったNote Offが過ぎるまでは出力側の使用中状態を維持します。
- 進捗・正誤・完了・手本表示・現在位置を初期化します。新しい曲を自動開始しません。「練習開始」「もう一度」「手本を聴く」はモデルの先頭から始めます。
- 各選択に新しい要求IDを付けます。古いXML取得結果、解析・描画完了、描画エラーを無視します。
- ScoreViewを要求IDで分離し、各OSMDが専用のDOMホストを持ちます。旧ホストを即座に切り離し、非同期loadが終了してから旧インスタンスを廃棄します。ResizeObserverと描画予約も解除します。
- 読み込み中は「楽譜を読み込み中…」。練習開始・もう一度・手本を無効化し、全音停止は利用できます。選択欄は常に変更可能です。
- 取得・XML形式・解析・対象音なし・表示の失敗時はエラーを表示します。前曲の楽譜・判定データを残しません。別の曲を選んで復帰できます。
- MIDI管理は曲選択の外で維持します。入出力機器の選択、接続、入力リスナーは再作成しません。押しっぱなしの鍵盤は、切り替え後も離してから押す必要があります。

DemoPlayerはReactやOSMDのDOMを操作しません。UIが再生位置を購読し、対応するカーソルを動かします。

## 対応範囲と曲の追加

1パート・1声部・単旋律の音高付き音符が対象です。収録曲はト音記号・4/4・四分音符と二分音符で作成しています。休符、和音、複数パート・声部・譜表、装飾音、タイ、反復は対象外です。既存の固定100 BPMと音価90%でのNote Offを維持します。XMLテンポを新たに解釈する処理やテンポUIは追加していません。

1曲追加する場合:

1. 対応範囲のMusicXMLを `src/scores/new-song.musicxml` に保存します。
2. `src/score/songCatalog.ts` の `songs` に一意のID、表示名、パート表記、`() => import('../scores/new-song.musicxml?raw')` を登録します。
3. ブラウザーで表示・音数・開始音・最後までの練習・手本を確認します。テストの曲一覧にも確認対象を追加します。
4. lint・型チェック・単体テスト・build・Pagesブラウザーテストを通し、mainへcommit/pushします。

アプリの判定・再生コードやMIDI音列を追加する必要はありません。ユーザーのファイル選択UI、永続保存、曲検索・編集、Phase 3機能はありません。

## 残っている確認・制限

- 上記8項目のChromebook + U2MIDI Pro + PX-100実機受入。
- OSMDの既存チャンクサイズ警告は継続しています。ビルドエラーではありません。
- MIDI予約消去非対応時は停止直後に出力の待ち時間があります。通信・描画に失敗した選択は利用できず、別曲を選択して復帰します。
- 大きなタイマー遅延や別タブへの移動では、既存仕様どおり手本を停止します。
