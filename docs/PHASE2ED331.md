# Phase 2E-D3.3.1 — original版手本の停止・再開始を修正

2026-09-29。D3.3の先読みの見やすさはユーザーが実機確認済みです。今回の手本修正は実装・自動検証とChromebookの実機受入を分けます。Phase 3は実装していません。

## 1. 根本原因と調査方法

生成済みの演奏順は正しく、forward repeatを停止条件にするコードもありませんでした。停止を引き起こせる経路は、表示領域の高さ変化によるOSMD全体の再描画と、DemoPlayerの150ms超の遅延による全体停止の組み合わせでした。

D3.3のScoreViewはResizeObserverで楽譜領域の高さも監視し、変化すると全体を再描画してカーソル対応・全段の矩形・符頭対応を再計算していました。反復回数の表示が現れる／消えると上部の高さと楽譜領域の高さが変わります。この更新が発音タイマーを遅らせると、DemoPlayerが安全停止していました。

旧コミット `c30e12b320b532cc3a242220ea4d909e16b6e392` で、実ブラウザの実時間を使用し、「再生中にOSMDのSVGが実際に置き換わった場合だけ500msの描画負荷」を加えました。初回5小節目と練習完了後の先頭再生の両方で旧停止メッセージを再現しました。[再現記録](PHASE2ED331-reproduction.json)

修正後は同じ条件で再生中の全体再描画がなく、両方とも6小節目へ進むことを確認します。実機の性能トレースは受け取っていないため、これを実機内部の唯一の原因と断定しません。コード経路と負荷下の再現を根拠とした修正です。

## 2. なぜ初回5小節目で止まったか

5小節目で「反復 1回目」が加わり、表示領域が縮むことが再描画の引き金でした。forward repeatは戻り先のメタデータとして使うだけで、初回4→5では通常の次Occurrenceへ進みます。今回、反復表示用の行をあらかじめ確保し、内部の高さ変化をOSMD全体の再描画条件から外しました。ウィンドウの高さ・表示幅が本当に変わった場合の再配置は維持します。

演奏順は全モードとも **1〜30→5〜30（計56小節Occurrence）** です。

| モード | SequenceOccurrence数 | MIDI Note On数 |
| --- | ---: | ---: |
| 右手 | 88 | 228 |
| 左手 | 144 | 176 |
| 両手 | 204 | 404 |

和音があるためOccurrence数とNote On数は異なります。各Occurrenceの `sequenceIndex / measureNumber / repeatPass` を[全件の監査JSON](PHASE2ED331-sequence.json)へ出力しました。反復区間外のrepeatPassはnullです。更新用コマンドは `WRITE_DEMO_AUDIT=1` を設定して `npx vitest run tests/unit/demoLifecycle.test.ts`。通常のテストはこのファイルを書き換えません。

## 3. なぜ練習後に無音・即停止に見えたか

完了した練習位置の30小節目から手本の1小節目へ戻る際、反復表示が消えて同じ再描画と遅延停止の経路へ入りました。この経路も旧版で再現しています。最初の音だけ短く鳴ったか、発音を認識する前に停止したかは実機ログなしでは区別できません。

また旧「現在位置から」はcompletedを解釈せず末尾Occurrenceを選んでいました。短い残りだけで終わるケースも、操作に対して分かりにくい状態でした。今回のresolverはcompleted時の先頭fallbackと理由表示を担当します。

## 5. Demo lifecycle

開始位置と音列を検証 → 前回のタイマー・購読を解除 → 新セッションを発行 → 出力開始 → 練習判定を同期停止 → 初期位置を反映 → 単調増加時計を開始、の順です。初期位置の表示処理時間を演奏開始後の遅延に含めません。

主状態はPlaybackSequence上のsequenceIndexです。同じ5小節目でもpass1とpass2は別Occurrenceです。開始時にstartSequenceIndex、現在位置、preview、表示エラー数、期限超過音数を初期化します。先頭以外の開始時はresolverが決めたOccurrenceを使用します。AbortControllerはタイマー主体の現在の構成では不要で、世代トークンとタイマー解除を使います。

終了判定は再生対象の全Note Off時刻の最大値です。originalでは30小節目pass2の最後のOff後だけcompletedになります。5pass1、30pass1、5pass2では継続します。終了後に音の追跡情報と全予約タイマーを空にし、練習位置を復元します。

## 6. Demo start resolver

開始位置は `resolveDemoStart(plan, start)` に集約しています。UIは選択種別・練習の現在index・completedを渡し、開始indexを推測しません。

| 指定 | 結果 |
| --- | --- |
| beginning | 練習のidle / 途中 / completedに関係なくindex 0 |
| current、練習中 | 現在のOccurrence。反復2回目なら2回目を維持 |
| current、completed | index 0、adjusted=true、理由メッセージ |
| measure | その小節の最初のOccurrence。10小節目ならpass1から30→5〜30 |
| currentだが対象なし | 明示的なエラー。無音のままplayingにはしない |

タイ継続位置からの手本用持続音の再構成と、対象のない小節から次の対象への移動は既存仕様を維持します。

## 7. generation / token

音声タイマーと出力中断購読はDemoPlayer.generation、再生をまたぐ送信失敗はplaybackSessionで無効化します。先読みは別の独立トークン、MIDI出力の表示タイマーも独立したdisplayGenerationを持ちます。先読みの再配置で音声側のgenerationは変わりません。

テストではAの音声・先読み・出力表示タイマーと中断購読を保存し、停止→B開始後に強制実行しても、Bの状態・タイマー数・MIDI送信数・clear回数が変わらないことを検査します。

## 8. timerと遅延の扱い

音声は次の発音または最終Offを待つタイマー1本、先読みは表示用1本、MIDI出力表示用は1本です。停止・終了で全て解除します。

描画遅延が150msを超えた発音、または既にNote Off期限を過ぎた発音は、遅れてまとめて送らずスキップします。後続の発音は開始時からの元の絶対時刻を維持し、手本全体を停止したり時間軸をずらしたりしません。通常条件では全音を元の音高・時刻で送信するテストを通します。

これはブラウザのメインスレッド停止中の発音を保証する仕組みではありません。過度の負荷で音が欠けた場合は開発者用のExpired attacksに残ります。別タブへの移動時の停止は従来どおりです。

## 9. MIDIOutput.clear()

clearは明示的な停止、出力変更・切断、送信エラーの停止処理でだけ使用します。新規演奏の予約より前に同期実行し、先読み・反復ジャンプ・完了から呼びません。各発音のNote OffとAll Notes Off（CC123）も送ります。

未来のNote OnはMIDIポートへまとめて予約せず、未来に予約するのはNote Offだけです。clear非対応の場合は残ったOff期限まで新しい演奏を待たせ、前回のOffが次の音を消さないようにします。遅れて走る出力表示タイマーは世代を検査し、新しいplaying状態を書き換えません。

## 10. look-aheadとの分離

D3.3の先読み時刻・段の選び方・30→5で即時に反復先を表示する動作を維持します。DemoPreviewSchedulerは表示通知だけを発行し、MIDI出力やDemoPlayerへの参照を持ちません。通知でsequenceIndexを進めたり、音列を再生成したりしません。リサイズで段対応が変わったときも表示通知だけを再予約します。

通常のカーソル位置は発音時刻に合わせて同期反映し、スクロールアニメーションの完了は待ちません。スクロール・カーソル追従・実行中の再描画が失敗しても、ロード失敗として曲と再生を初期化せず、表示上の注意として扱います。最初の読み込み・解析・対応検証失敗は従来どおり開始を禁止します。

## 11. completed時のcurrent

「練習が最後まで終わっているため、最初から手本を再生します」と表示して、先頭から再生します。元の練習完了状態は保持し、手本終了後に戻します。「最初から」を明示した場合は常に先頭から再生し、このfallbackの説明は不要です。
