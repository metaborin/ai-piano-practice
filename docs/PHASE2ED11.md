## フィードバックと判定

楽譜パネルの小節・現在位置の直下に常設しました。メッセージ1行＋音名2行の高さを常に確保し、判定のたびに五線譜を動かしません。パネル内で縦スクロールすると上端に追従します。モーダルは使わず、`role="status"`、`aria-live="polite"`、`aria-atomic="true"`で読み上げに対応します。長い音名列は1行に省略表示し、全文はtitleとアクセシブルなテキストに残します。

`MomentMatchFeedback`は `status` と `expectedMidiNotes / matchedMidiNotes / missingMidiNotes / unexpectedMidiNotes` を返します。配列は試行ごとにコピーし、内部Setのリセットで過去の通知を変えません。Sessionは判定されたTargetのindexも保持するため、正解で現在位置が進んでも前の判定と新しいTargetを混同しません。

- 一致音＝その試行で受信した必要音。不足音＝期待音から一致音を除いたもの。
- C/E/G期待でC/Eだけならpendingのまま。300ms境界は従来どおり含め、301msのタイマーでG不足を確定します。pending中は赤くしません。
- C/E/Aならその場でincorrect、matched C/E・missing G・unexpected A。余分な音は楽譜に追加せず「ちがう音：A4」と表示します。
- 単音C期待でDならすぐincorrect、missing C・unexpected Dです。
- 重複Note On・押し続けた鍵盤・Note Offを正解として数えない既存仕様を維持します。弾き直す際は鍵盤を離してください。

赤表示は新しい試行のpending、正解、練習開始、もう一度、モード変更、曲変更、手本開始、入力切断時の状態整理で解除します。中断した判定タイマーは世代番号で無効化します。

## ScoreNoteとOSMD符頭の対応

`ScoreNoteRenderMap`が同一XML由来のScoreModelとOSMDを対応付けます。

1. OSMDカーソルの音符を公式APIで巡回し、XML小節の開始拍＋VoiceEntryの拍を正確なBeat分数に変換。
2. 拍・Staff・MIDI音高でScoreNoteへ対応付け、`EngravingRules.GNote(note)`でGraphicalNoteを取得。
3. `getNoteheadSVGs()`は和音全体の符頭を返すため、GraphicalNote自身の`vfnoteIndex`（OSMDが設定する和音内の音高index）で該当する符頭を選択。SVGのnth-childや全音符のDOM順には依存しません。
4. Staff宣言省略の既存曲をOSMDが1段へ正規化した場合だけ、同じ開始拍・音高が原本と描画の両方で一意なら対応可能とします。曖昧な推測で別音符を選ばず、対応不能時は既存の表示失敗経路で開始を禁止します。

incorrectのmissing pitchをTargetのsourceNotesへ照合し、タイ継続を除いたScoreNote IDを赤にします。両Staffの同じpitchは物理的な打鍵として統合したまま、該当する両方の符頭を対象にできます。正解した構成音は通常色、現在位置は既存の緑帯です。

符頭グループと、そのグループ内のglyph pathだけに赤いfill/strokeを指定します。元のstyle属性を保存し、解除時に元の値または属性なしへ正確に戻します。符幹・五線・タイ・余分な音符は変更しません。リサイズ後は新しい描画への対応を作り直し、現在の判定だけを再適用します。曲変更で古いOSMDインスタンスと着色参照を破棄します。

## 手本の開始位置と練習位置

開始位置は `DemoStart` の `beginning`、`moment + momentId`、`measure + measureIndex` です。`DemoPlayer.playFromMoment(id)`も公開し、将来の楽譜タップから利用できます。今回タップUIは追加していません。

- 最初から：拍0から、冒頭休符を含めて従来どおり再生。
- 現在位置から：PracticeSessionの現在Targetが持つScoreMoment IDを渡す。選択モードの音だけを再生。
- 指定小節から：XMLの小節番号を選択肢に表示。内部は同じ番号が繰り返されても区別できる小節indexを保持。小節開始以降の最初の対象Targetを解決。対象がなければ次の対象へ進み、曲末まで対象がなければ「このパートの音がありません」と表示して発音しません。

開始位置以降のデータ生成は再生エンジン側で行い、UIは音列をsliceしません。既存のテンポ優先順位（MusicXML→Song→100 BPM）・途中テンポ・休符・同時音・90%ゲートを保持します。**開始点ですでに持続中の音・タイは残りの長さを新しいNote Onで再現します。** これは途中から聴く場合の開始音の再構成であり、先頭からのタイ途中の再発音は従来どおりありません。

PracticeSessionは手本開始前のidle/practicing/completedと位置・正解数を保持して判定だけを止めます。手本表示はDemoPlayer自身のindexを使用し、終了・停止時は元の練習位置へ戻ります。練習中だった場合は続きから再開でき、手本前の途中和音は引き継ぎません。曲・モード変更時は新しいPlanを読み込み、古い復帰状態は破棄します。

DemoPlayerはReact/OSMD/DOMへ直接依存しません。通知アダプターを注入し、React側のflushSyncとScoreViewのlayout effectで指定カーソルを反映してから最初のMIDIを送信します。停止ではタイマー・通知世代・割込購読を取り消し、既存のNote Off、CC123、可能なら出力clearを使います。未来のNote Onをまとめて予約しない構造を維持しています。

## Chromebook + PX-100 実機確認

1. 公開URLを再読み込みして **Phase 2E-D1.1** を確認します。保存曲を残すためサイトデータは消去しません。「自分の曲」から実機確認済みのマイム・マイムを選び、MIDI入力・出力の接続機器を確認します。
2. 右手で練習開始し、楽譜上部の現在位置とフィードバックを同時に見ます。正解で「できた！」、誤答で「もう一度♪」が出ても楽譜が上下に動かないことを確認します。
3. 単音の期待音と違う鍵盤を押し、期待音符が赤くなり、「ちがう音」が実際の鍵盤名になることを確認します。鍵盤を離して正しく弾き直し、通常色へ戻ることを確認します。
4. 和音の1音だけを省き、300msまでは赤くならず、時間後に不足した符頭だけが赤くなることを確認します。次に1音を別の鍵盤へ替え、不足音・余分な音名が一致することを確認します。タイ継続を再打鍵対象にしない点は維持しています。
5. 練習を途中まで進め、位置と正解数を覚えます。「現在位置から」→「手本を聴く」で現在位置の音から鳴り、緑帯が追従することを確認します。手本中の打鍵では練習位置が進まないことも確認します。
6. 「停止」を押し、全音が止まり、20秒待っても再発音しないことを確認します。緑帯と練習位置が手本前へ戻り、その続きから弾けることを確認します。
7. 「2小節目から」（実XMLの小節番号）を選び、選択パートの最初の対象から鳴ることを確認します。終了まで聴いても元の練習位置・正解数が保たれることを確認します。開始点で持続中だった音は残りの長さで再発音します。
8. 左手・両手でも手順3〜7を確認します。「最初から」も従来のテンポ・タイ・休符で再生できることを確認します。
9. 赤表示中に「もう一度」、パート変更、曲変更を行い、赤が残らないことを確認します。再生中のモード／曲変更でも旧音が止まり、MIDI機器選択が維持されることを確認します。
10. きらきら星へ戻し、単旋律判定・完了・もう一度・テスト音C4・全音停止を確認します。再読み込み後に既存の保存曲が残ることも確認します。
