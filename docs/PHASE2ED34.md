# Phase 2E-D3.4 — 楽譜全体ナビゲータ

大きな楽譜と同じ原譜を縮小した「楽譜全体」を追加しました。青い半透明枠はメイン楽譜パネルの表示範囲、緑の細線は実際の練習／手本位置です。タップ移動はありません。Phase 3には進んでいません。Chromebook + PX-100 + U2MIDI Proの実機受入は別途必要です。

## 2. 全体楽譜の生成方式と第二OSMD

依頼の方式Bです。メインOSMDの描画済みSVGページをコピーし、それぞれの実際の位置・サイズを保った1つのSVG画像にまとめ、Blob URLの`img`として表示します。**第二OSMDは作成しません。overviewからOSMD.render()を呼ぶこともありません。**

ライブのSVG DOMを複製して画面へ置かないため、メイン楽譜のID・符頭データ・赤表示のセレクターと干渉しません。カーソル画像は含めません。画像は縦横比を保ち、原譜全体を収めます。originalも1〜30の原譜1回分で、展開済みSequenceを描き直しません。

## 3. 生成タイミングと初期表示

メイン楽譜の検証・表示完了を通知した後、次のrequestAnimationFrameで1回だけ画像を生成します。通常楽譜や練習開始の準備完了を画像の生成・decode待ちにしません。生成フレームの前に練習／手本が始まった場合は、待機状態になるまで生成を延期します。

1音進行、和音判定、赤表示、カーソル移動、反復、スクロール、パート変更、折りたたみでは生成しません。ウィンドウサイズ変更でも静的画像を作り直しません。

## 4. ViewportIndicatorの計算

スクロールパネルと楽譜ホストの実DOM座標の差から、パネル内で見えている領域を求めます。パネルの余白やボーダーを除き、概念的には次の計算です。

```text
topRatio = (scrollTop - 楽譜の開始offset) / 楽譜全体height
heightRatio = clientHeight / 楽譜全体height
leftRatio = (scrollLeft - 楽譜の開始offset) / 楽譜全体width
widthRatio = clientWidth / 楽譜全体width
```

境界を0〜1へ制限し、余白を含めて原譜の外へ枠がはみ出さないようにします。画像を収めた実寸へ掛けて、枠のtransform・width・heightだけを変更します。短曲では枠がほぼ全体を覆います。

## 5. 現在位置マーカー

ScoreViewがすでに持っているOSMDの描画位置表を生成時に保存します。Practice／Demo SequenceOccurrenceから渡される`sourceMoment.id`で原譜上の矩形を引き、静的画像の座標へ縮小します。独自の音列・小節別固定座標は持ちません。現在位置がないパートではマーカーを非表示にします。

手動スクロールは現在momentを変更しないため、枠だけが動きます。手本の先読み時も、枠が先に5小節目へ戻り、緑線は発音中の30小節目に残ります。実際の5小節目の発音後に緑線が戻ります。

## 6. スクロール同期と負荷対策

パネルのpassive scrollイベントをrequestAnimationFrameで1フレーム1回へ集約します。自動追従・先読み・現在位置へ戻る・指定小節開始も、実際に動いた同じパネルを監視します。位置通知からの更新要求も同じフレームへまとめます。

毎フレーム常時監視するループはありません。スクロールのたびにReact stateを更新せず、refから枠とマーカーのDOMだけを更新します。ScoreOverview自体はmemo化しています。更新関数にはXML解析・SVGコピー・OSMD操作を含めません（まだ生成していない最初の待機フレームのみ画像を作成）。

## 7. Resize対応

ResizeObserverでパネル・ミニマップ領域・楽譜ホストの変更を受け、同じフレーム処理へ集約します。画像の表示寸法を再計算し、元画像は維持します。

メインOSMDが既存のウィンドウ幅／高さ変更処理で段組を変えた場合、現在見えているsourceMoment群を初回画像上の位置へ対応付け、その範囲を覆う枠にします。この場合の枠は**小節・段のまとまりを示す概略範囲**です。再配置後も画像内の緑線は同じ原譜位置です。横方向は初回配置のときに正規化し、段組変更後の概略枠は原譜画像の横幅全体を使います。

## 8. 曲変更と破棄

曲のrequestIdでScoreViewとoverviewが一緒に入れ替わります。古いイベントリスナー・ResizeObserver・予約フレーム・画像load/errorハンドラーを解除し、Blob URLをrevokeします。遅れた画像通知にはdisposed検査を入れています。新しい曲を1回生成し、練習の先頭momentと新しいパネルのスクロール位置を反映します。

MIDI接続は既存の管理のままです。曲選択に伴う消音などは既存のSongSelectionが担当し、overviewは介入しません。

## 9. 反復とパート変更

反復2回目も同じ`sourceMoment.id`の位置を使います。originalの原譜画像は30小節のまま、markerとviewport枠だけが30→5へ戻ります。既存の「反復1回目／2回目」表示は維持しています。

右手／左手／両手の変更、もう一度、練習・手本の途中開始、停止後の練習位置復帰は、ScoreViewへ渡る既存の現在位置に従います。これらによる画像の再生成はありません。

## 10. MIDIとの分離

overviewの入力は描画済みホスト、レイアウト、読み取り用ScoreModel、現在moment、演奏中かどうかだけです。MIDI出力・DemoPlayer・PracticeSession・Sequenceを操作する関数を渡しません。これらの制御層をimportしないことをテストしています。

clear、All Notes Off、stop、generation変更、音列変更を行いません。D3.3.2の「全MIDI構成音を送信後にカーソル更新」も維持します。新たなミニマップ位置反映はその後の描画フレームで行います。

## 11. UI・折りたたみ・アクセシビリティ

sticky進捗欄の横へ置き、メイン楽譜を広く残します。Chromebook幅では画像領域100px高、見出しは44px以上の操作領域です。狭い画面では横幅100px・画像領域80px高へ縮小し、上へ積み重ねて通常楽譜を狭めないようにしました。「楽譜全体」の見出しで折りたためます。

画像・枠はpointer-eventsなし、aria-hiddenです。タップして小節へ移動する操作はありません。代わりに「現在○小節目付近」と色の役割をスクリーンリーダー用テキストに持ちます。折りたたみはネイティブdetails/summaryでキーボードでも操作できます。

## 12. エラー分離

SVG画像生成、画像decode、枠計算の失敗はoverview内で処理します。「全体表示を作成できませんでした」と表示し、通常楽譜・練習・手本は継続できます。別曲を選ぶと新しいoverviewを生成します。失敗からの復帰と、旧画像の遅れた完了通知をブラウザテストしています。

## 13. 生成回数と診断

「開発者用」→「全体表示の診断を更新」で以下を手動確認できます。

- Overview render count：その曲の静的画像生成成功回数。通常は1。
- Overview render time：SVGコピー・画像URL作成までの時間。非同期decodeや実機GPU描画時間は含みません。
- Viewport update count：枠・マーカーの更新回数。進行・スクロールで増えて正常です。

自動テストでは3モードの反復前後・折りたたみ前後もrender count=1で、画像URLが同じことを確認しました。XMLSerializerの呼び出しを監視し、スクロール・手本中に静的画像の生成処理が再実行されないことも検証しています。スクロール中のメイン楽譜DOMの追加・削除は0回でした。100件のスクロールイベントを1回へまとめる単体テストもあります。

## 18. 未解決事項・対象外

Chromebook + PX-100での実発音・負荷・小さい画面での見やすさは実機確認待ちです。モックMIDIのsend成功は実発音の保証ではありません。

長い楽譜ほど縮小画像は細かくなります。譜読み用の表示ではなく、曲の形・前半／後半・表示範囲を示す補助です。幅変更で段組が変わった場合の青枠は概略範囲です。

タップ移動、全体表示からの開始位置指定、テンポ変更、譜面解釈の追加、AIコーチ等は実装していません。D3.3.2同様、ブラウザ全体の長時間停止による期限超過の発音まで保証するものではありません。実機確認が済むまではD3.4全体を完了扱いにしません。
