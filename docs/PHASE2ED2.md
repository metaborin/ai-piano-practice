## 自動スクロールの設計

楽譜カード全体を画面高から余白を引いた範囲に収め、五線譜だけを縦・横にスクロールできるようにしました。短い楽譜は自然な高さのままです。小節番号・進捗・フィードバック・「現在位置へ戻る」は同じカード上部に残り、五線譜とは別の領域を確保します。楽譜のスクロール領域はキーボードフォーカス可能なregionです。

`ScoreFollow`はOSMDが実際に描画した緑のカーソルと表示領域の矩形を読みます。小節の高さ・段数・曲名を仮定しません。カードの上部情報、画面端、スクロール領域によるクリップを考慮します。

- 現在位置が余裕を持って見えているときは移動しません。
- 上側へ外れた、下端に近づいた、次段へ移った場合だけ移動します。
- 移動先は、カーソルの高さを差し引いた表示可能範囲の約45%を基準にし、少し先を見られるようにします。末尾などでは実際のスクロール可能範囲に収めます。
- 横にはみ出す場合も必要な分だけ移動し、狭い画面でカーソルを見失わないようにします。
- ページ自体を別の位置まで動かしていた場合は、必要なときだけ楽譜カードを画面内へ戻してから、楽譜内部を合わせます。

通常の進行はブラウザのsmoothスクロールを使います。OSの`prefers-reduced-motion`設定では即時移動します。指定位置の開始・復帰・リセットは即時移動し、前のsmooth移動も取消します。

## 追従を発生させるイベント

| イベント | 動作 |
| --- | --- |
| 練習で次Stepへ進む | 必要な場合だけ追従。誤答・pendingなど位置不変の更新では動かさない |
| 手本で次の段へ進む | 縦方向へ必要に応じて追従。横方向は各位置で必要性を確認 |
| 手動スクロール | そのまま保持。scrollイベント監視・常時ポーリングによる引き戻しはしない |
| 現在位置へ戻る | 手本中はDemo位置、それ以外はPracticeTargetを即時表示 |
| 手本開始 | 指定カーソルへ移動→必要なページ／楽譜内スクロール→最初のMIDI送信 |
| 手本停止・終了 | D1.1で保持した元の練習位置へカーソルと画面を復帰 |
| 練習開始・もう一度 | 先頭Targetと表示範囲へ戻る。すでに先頭でも手動スクロールを戻せる |
| パート変更 | 既存のPlan再生成・練習リセットに加え、新しい先頭を表示 |
| 曲変更 | 発音・判定停止、旧描画の後始末、新曲の読み込み完了後に先頭を表示 |
| 幅変更による再描画 | 対応表と赤表示を作り直し、追従中だった現在位置を表示 |

初期ページ表示だけで勝手に楽譜へ飛ばすことはありません。取込確認用の非表示OSMDには追従を有効にせず、ページを移動させません。非同期の旧曲読み込みは既存のrequestId・キャンセル・インスタンス分離で無効化し、旧表示への追従が新曲へ影響しない構造です。

## 練習／手本カーソル・指定小節との連携

D1.1のPracticeSessionとDemoPlayerのindex分離を維持しています。ScoreViewへ渡す表示中のMoment IDを追従対象とし、手本中だけDemo位置を使います。手本停止・完了後は元の練習位置と正解数を保持し、表示も戻します。

「最初から」「現在位置から」「指定小節から」は既存のDemoStart／playFromMomentを使います。UIで音列を切ったり、別の再生エンジンを追加したりしていません。小節候補はScoreModelの実際のmeasureNumberだけを表示し、番号の欠番を埋めません。内部の小節indexで同じ表示番号の複数出現も区別します。

既存の同期通知アダプター（React側flushSync）とScoreViewのlayout effect内で、カーソル移動に続いて即時スクロールを行います。その完了後にDemoPlayerが時刻基準を設定して発音します。ブラウザテストは最初のMIDI送信時点のDOMを読み、後半の小節番号とカーソルの画面内表示を確認します。DemoPlayerからReact・OSMDのDOMは操作しません。

## 後半の赤表示・長時間再生・性能

ScoreNoteRenderMapは全曲を対応付ける既存方式です。後半小節の不足音でも同じID・拍・Staff・音高の対応を使います。スクロールによってSVGを破棄しないので、移動だけで対応表を再生成しません。リサイズ時は既存どおり再生成・再適用し、曲／パート／再開始時の解除も維持します。

手本のスケジューラーは変更していません。次の発音時刻のタイマーを1つだけ保持し、未来のNote Onを大量にMIDIへ予約しません。Note Offは従来どおりtimestamp指定です。MIDI出力の表示タイマーを含めても同時に最大2つで、音数に比例して蓄積しないことをfake timerと実MidiOutputManagerで確認します。

停止・曲変更ではタイマー世代を無効化し、Note Off・CC123・利用可能ならclearを送ります。clearがない場合に古いNote Offが終わるまで再生を待つ既存仕様も維持します。二重startは無視し、完了後・停止後の旧再生は再開しません。

長曲向けには手本データ生成の拍→Target検索をMapに変更しました。従来の「各音について全Targetを先頭から探す」処理をなくし、全音列の終了時刻も引数展開を使わず走査します。通常の1Step更新でScoreModel・Plan・OSMD・対応表を作り直しません。

カーソル／符頭対応の異常巡回ガードは、notes＋rests＋measuresから上限を導出し、固定の5000位置を前提にしません。**従来の取込保護上限（note/rest合計1000要素・500小節、XML/MXLサイズ等）は維持しています。** 4／8／16／32小節など今回の検証曲専用の制限は追加していません。全SVG描画方式を維持しており、全曲の仮想描画や厳密なChromebook性能保証は今回の範囲外です。

## Chromebook + PX-100 実機確認手順

1. 外部で対象範囲を広げたマイム・マイムSECONDOのMusicXML/MXLを作成し、元スキャン譜と音高・音価・小節・テンポを照合します。アプリは画像から音符を推測しません。元ファイルを保管してください。
2. 公開アプリを再読み込みし、**Phase 2E-D2** を確認します。保存曲を残すためサイトデータは消去しません。「＋ 曲を追加」で拡張版を別名で登録します。
3. Validation Reportで実際の小節数／番号、Staff2、Voice、Moment、3モードのStep数、テンポ、対応状況を確認します。BPMは従来どおり四分音符換算です。未対応理由があれば開始せずXMLと対応範囲を確認します。
4. MIDIを接続し、入力・出力機器とテスト音C4を確認します。右手で開始し、段をまたいで進むと現在位置と少し先が見えること、各音で画面が細かく動かないことを確認します。
5. 楽譜内を指で別の場所へスクロールし、停止中は引き戻されないことを確認します。「現在位置へ戻る」と次の正解Stepで必要な位置へ戻ることを確認します。
6. 中盤・後半で音を間違え／和音の1音を省き、該当符頭の赤表示と不足／余分な音名が楽譜付近に残ること、弾き直すと解除されることを確認します。
7. 練習位置を覚え、「指定小節から」で後半の小節を選びます。その小節が表示された後でPX-100が鳴り、以降の段を追従することを確認します。「現在位置から」「最初から」も確認します。
8. 手本中に別の位置を手動で見て、同じ段の各音で引き戻されず、「現在位置へ戻る」で手本位置へ戻れることを確認します。
9. 手本を停止し、音が止まり、20秒待っても再発音しないこと、元の練習位置へカーソルと画面が戻ることを確認します。曲末まで再生した場合も元の練習位置へ戻ることを確認します。
10. 左手・両手でも同じ確認を行います。後半で「もう一度」「パート変更」を押すと新しい練習の先頭が見え、古い赤表示が残らないことを確認します。
11. 長曲の手本を数回繰り返し、二重発音・停止後の再発音・極端な操作遅延がないことを確認します。別タブへ移動すると安全のため手本は停止する既存仕様です。
12. 再生中にきらきら星へ変更し、新曲の先頭表示、旧音停止、MIDI選択維持を確認します。短曲の練習・完了・もう一度も確認してください。
